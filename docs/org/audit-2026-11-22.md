## 1. Executive summary

- **Що сильне.** Виробництво повністю автоматизоване й відтворюване: сценарій `epNN.py` → Gemini TTS (`gem/gtts.py`) → Whisper-звірка (`gen_full.py`, `audit_vo.py`, `align.py`) → Remotion (`rv/`) → `yt.upload` → `finalize.py` з PASS/FAIL. Сайт стабільний: 36 з 40 деплоїв успішні, решта 4 скасовані, без падінь. SEO/GEO-обв'язка повна. Є єдина SQLite-база з YouTube Analytics, Search Console, нішею, 504 конкурентами (62 тис. відео) і новинами. Факти для довгих відео перевіряє незалежний агент таблицею «твердження ↔ URL ↔ PASS» (`guide*_factcheck*.md`).
- **Секрети в git не потрапили.** Токени й ключі лежать у `studio/{tg,gem,yt,pult}/.*` з правами 600 і закриті `studio/.gitignore`. В історії з 603 комітів їх немає. Прибрати варто дві дрібниці: chat_id власника захардкоджений у публічному коді, а посилання на артефакт «Доступи» лежить у публічному MIGRATION.md.
- **Чого критично бракує.** Немає ідемпотентності й захисту від гонок. Агенти Диспетчера (до 4 паралельно) і ще 18 задач пишуть одні й ті самі JSON (`ideas.json`, `pending_comments.json`, `tiktok.json`, `activity.json`, навіть `yt/token.json`) без блокувань і атомарного запису, а потім пушать у дві гілки. Заливка на YouTube не ідемпотентна. У `yt.api` немає timeout, retry, обліку квоти і журналу запусків.
- **Головний операційний ризик.** OAuth-застосунок YouTube працює в режимі Testing, тому refresh-токен живе 7 днів. Найближче він закінчиться 25.11 ~10:00Z. Разом із ним одночасно зупиняться заливки, аналітика і Search Console.
- **Дані.** Ланцюжок «новина → тема радара → ідея → відео → публікації → метрики» не з'єднаний. Ідея не знає свого відео, новина не має story_id, публікації розкидані по 5 файлах. `traffic` і `site_*` перезаписуються, тому історії немає. KPI «годин довгих» захардкоджений (`hq_data.py`: `long_hours=10.1`), а `estimatedMinutesWatched` взагалі не збирається.
- **Метрики.** Через API можна відповісти, які формати дають підписки і % перегляду. Не можна відповісти про 3-секундне утримання, CTR обкладинок, переходи на сайт і в Telegram, метрики TikTok і переглядів Telegram. Тест обкладинок у `thumb_test.json` спирається на CTR, якого YouTube Analytics API не віддає: показів і CTR в API немає, офіційний шлях — експорт зі Studio або вбудований «Test & compare».
- **Вердикт.** Нова інфраструктура не потрібна. Достатньо одного модуля утиліт (атомарний запис, lock, retry, журнал), 6–7 нових таблиць у тій самій SQLite і одного щоденного звіту.

## 3. Data flow map

```
ДЖЕРЕЛА: RSS OpenAI/Google/DeepMind · HTML anthropic.com/news · HN Firebase API · HTML dou.ua/lenta
         · Reddit/Verge/ain/dev.ua (агент читає вручну, у базу не пишеться) · YouTube Data API (ніша, конкуренти, autocomplete)
         · Search Console API · YouTube Analytics API · Telegram (вебхук → pult → inbox.py)
  │
  ▼ ingestion: lake.py news (*/4 год), niche/comp/history, outliers.py, analytics_db.sync, lake.ingest (GSC)
  ▼ raw: окремого raw-шару немає, одразу таблиці news/niche/comp_videos/daily (без payload)
  ▼ normalize: частково (дата→YYYY-MM-DD, lang_of за кирилицею); у Anthropic published порожній, у dou published=fetched
  ▼ dedupe: news.url PK (точний URL); niche (video_id,fetched); між джерелами немає
  ▼ score/rank: агент радара оцінює «x/10» у Markdown → lake.ingest_research парсить → research;
                ideas.py: бал = demand×fresh×show×fit×prior(format)
  ▼ editorial queue: ideas.json (status new→approved→in_work→done) → [queue.json — НЕМАЄ] → слот у тригері-нагадуванні
  ▼ generation: epNN.py (SCENES: hook/text/gsay) + meta.py + Remotion + TTS
  ▼ review: агент-фактчекер (guide*_factcheck_independent.md), audit_vo/voice_check, finalize/audit PASS, дизайнер (кадри 0/1 с/80%)
  ▼ publish: yt.upload+schedule → uploaded.json; post_comments.py; tg.video → telegram_post у статті; vidIQ → tiktok.json; git push → Pages
  ▼ metrics: daily/traffic/snap (YT), site_* (GSC), getChatMemberCount (у HQ, без історії); TikTok — вручну
  ▼ analysis: analytics_db report/top, lake ask, forecast-audit, growth-loop (нд), CSO (пн)

```

## 4. Gap analysis

### 4.1 Якість даних (відповіді на питання брифу)

| Питання | Факт |
|---|---|
| content_id / canonical_url | Для відео є `videos.id`, для статті `posts.slug`, для новини `news.url` (не канонізований). Наскрізного content_id немає. Найкращий кандидат — slug випуску (`ep81_tier_kids`), бо він уже є в `uploaded.json` і `videos.slug` |
| Дедуп між джерелами | немає |
| original_url / source / published_at / fetched_at | є в `news`; у Anthropic `published=''` (23 рядки), у dou `published=fetched`; `language`, `topic`, `entities` немає |
| Версіонування | немає: `insert or ignore` назавжди фіксує перший заголовок. Зміни метаданих YouTube логуються ad hoc (`backup_meta_*.json`, `retitle_2026-11-10.json`) |
| raw / normalized / analytics | змішані в одній базі; аналітика відокремлена таблицями, raw немає. Для цього масштабу це прийнятно |
| Історія вибору | частково: `research` зберігає всі теми дня з оцінкою і планом, отже альтернативи видно. Зв'язку «тема → ідея → випуск» немає |
| Новина → відео → публікація → метрики | `videos.id ↔ posts.youtube` (76/80) і `videos.slug ← uploaded.json`. Ідея ↔ відео: 0. TG і TikTok ↔ відео: лише в JSON (`experiments.json.tg_post`, `tiktok.json`) |
| Інші дефекти | `traffic` — кумулятивно з 01.01 з перезаписом; `site_queries`/`site_pages` — період, що росте з 01.10, тому тижневої динаміки немає; `comp_ai` дропається при кожному запуску; `daily` не має рядків за дні з нулем переглядів; SQLite у rollback-journal без `busy_timeout`, хоча пише кілька агентів |

### 4.2 Контент-пайплайн

- **Редакційна цінність.** Це не просто переказ. RUNBOOK вимагає тезу «що це означає для тебе» і вердикт, а переможні рубрики (тір-лист, «ШІ для професії») за природою власні. Новини продуктів у Shorts закрито 21.11 через низьке утримання.
- **Гачок 0–2 с.** Є поле `hook` у сцені, чекліст і ротація типів гачка. Вимірювання немає, див. 4.3.
- **Аудиторія і позиціонування.** Чіткі: україномовні нетехнічні користувачі, робот Байт, «на ти», без рос. джерел.
- **Шаблони.** Shorts, довгі, обкладинки (Thumb2/3/4, LongThumb, ShortThumb) — композиції Remotion. Окремого шаблону TikTok немає: той самий рендер і інший підпис. Для TikTok цього достатньо.
- **Фактчек.** Для гайдів зроблено добре (claim ↔ URL ↔ PASS). Для Shorts факти лежать у коментарях `epNN.py`, незалежний файл є не завжди. Правило «не вигадувати» прописане.
- **Human review.** Немає. Власник дав постійний дозвіл, публікують YouTube (за розкладом), TG і TikTok (vidIQ) автоматично. Контроль якості цілком агентний.
- **A/B.** Зберігаються лише стиль обкладинки (`thumb_test.json`) і разові перейменування. Варіанти hooks, titles і CTA не зберігаються. Тест обкладинок за CTR через API неможливий.

### 4.3 Метрики: на що система може відповісти

| Питання | Зараз | Офіційний шлях |
|---|---|---|
| Теми з найкращим retention | лише за форматом (`avg_pct`); тем-тегів немає | додати `topic` у `videos` (з ідеї) |
| Hooks і 3-секундне утримання | ні | API: `dimensions=elapsedVideoTimeRatio`, `metrics=audienceWatchRatio,relativeRetentionPerformance`, `filters=video==ID`, точки 1–10% як proxy. Для Shorts перевірити одним запитом. «Viewed vs swiped away» є лише в Studio, звідти й експортувати |
| Формати, що дають підписки | так (`report`: підп/1000) | додати `subscribersLost` |
| Теми, що працюють у пошуку YouTube | частка `YT_SEARCH` є (2 691 перегляд) | `insightTrafficSourceDetail` при `insightTrafficSourceType==YT_SEARCH`: пошукові терміни на відео |
| Пошук TikTok | ні | API без аудиту недоступний; vidIQ `tiktok_profile_videos` і Studio TikTok — вручну |
| Переходи на сайт, TG, email | ні (UTM немає; Cloudflare Web Analytics не збирається) | UTM у посиланнях з описів (`utm_source=youtube&utm_content=<video_id>`); Cloudflare GraphQL Analytics API (RUM) для рефереров; TG — окремі invite-лінки на платформу (`createChatInviteLink`) + оновлення `chat_member` з полем `invite_link`. Email-каналу немає |
| Години довгих (YPP) | захардкоджено 10.1 | `estimatedMinutesWatched` з `creatorContentType` |
| Покази і CTR | ні | **в API немає.** Щотижневий CSV-експорт зі Studio → імпорт; для обкладинок — «Test & compare» у Studio |
| Що повторити, а що прибрати | частково (forecast-audit, growth-loop) | зв'язок ідея → відео + щоденний звіт |

## 5. Data model proposal (мінімальне розширення існуючої SQLite)

Наскрізний ключ `content_id` = slug випуску (`ep81_tier_kids`, `guide1`). Він уже є в `uploaded.json`, папках `eps/` і `videos.slug`. `ideas.json` лишається форматом обміну для агентів, а база синхронізує його (`ideas.py` пише в обидва місця, поки агенти не перейдуть).

```sql
PRAGMA journal_mode=WAL;            -- паралельні читачі під час запису збирача
-- 1) новини: канонізація й дедуп (міграція ALTER, без перебудови)
ALTER TABLE news ADD COLUMN canonical text;   -- без utm/#/www/кінцевого '/'
ALTER TABLE news ADD COLUMN story_id text;    -- sha1(нормалізований заголовок) або canonical першоджерела
ALTER TABLE news ADD COLUMN lang text;
CREATE INDEX IF NOT EXISTS news_story ON news(story_id);
CREATE INDEX IF NOT EXISTS news_pub ON news(published);

-- 2) ідеї = editorial queue (дзеркало ideas.json + статуси черги)
CREATE TABLE IF NOT EXISTS ideas(
  id text primary key, title text, format text, channels text, by text, source text,
  research_date text, research_n int,           -- → research(date,n): «чому обрали, які були альтернативи»
  story_id text,                                -- → news.story_id
  demand int, fresh int, show int, fit int, score real, prior real,
  status text check(status in ('new','approved','scripted','factchecked','voiced','rendered','scheduled','done','rejected')),
  slot_at text, content_id text, decision text, added text, updated text);

-- 3) публікації всіх платформ (замінює 5 реєстрів як джерело правди; JSON лишаються логами)
CREATE TABLE IF NOT EXISTS publications(
  content_id text, platform text check(platform in ('youtube','tiktok','telegram','site')),
  ext_id text, url text, scheduled_at text, published_at text, via text, status text,
  primary key(platform, ext_id));
CREATE INDEX IF NOT EXISTS pub_content ON publications(content_id);

-- 4) варіанти упаковки (A/B і історія змін)
CREATE TABLE IF NOT EXISTS variants(
  content_id text, kind text check(kind in ('hook','title','thumb','cta','description')),
  value text, active_from text, active_to text, note text);

-- 5) метрики: доповнити й не перезаписувати
ALTER TABLE daily ADD COLUMN minutes real;      -- estimatedMinutesWatched
ALTER TABLE daily ADD COLUMN subs_lost int;
ALTER TABLE videos ADD COLUMN topic text;       -- з ideas
CREATE TABLE IF NOT EXISTS traffic_daily(video_id text, date text, source text, views int, primary key(video_id,date,source));
CREATE TABLE IF NOT EXISTS retention(video_id text, ratio real, watch_ratio real, rel_perf real, fetched text, primary key(video_id,ratio,fetched));
CREATE TABLE IF NOT EXISTS search_terms(video_id text, term text, views int, period text, primary key(video_id,term,period));
CREATE TABLE IF NOT EXISTS studio_export(video_id text, period text, impressions int, ctr real, shown_in_feed int, viewed_pct real, file text, primary key(video_id,period));
CREATE TABLE IF NOT EXISTS tg_daily(date text primary key, members int, joins_by_link text);   -- JSON {link_name: n}
CREATE TABLE IF NOT EXISTS tiktok_daily(post_url text, date text, views int, likes int, comments int, shares int, src text, primary key(post_url,date));

-- 6) журнал запусків = логи + моніторинг + квота
CREATE TABLE IF NOT EXISTS runs(job text, started text, finished text, ok int, rows int, quota_units int, err text);
```

Зв'язки: `news.story_id ← ideas.story_id`; `research(date,n) ← ideas`; `ideas.content_id → publications.content_id → videos.id (platform='youtube', ext_id)` → `daily`, `traffic_daily`, `retention`, `search_terms`, `studio_export`; `posts.slug ↔ publications(platform='site')`. Для `site_queries`/`site_pages` писати `period` як один день (`date`=`period`), тоді історія накопичується без зміни схеми.

## 6. Integration plan (покроково, мінімальні зміни)

1. **Токен.** Власник переводить OAuth consent screen у Production. Після цього один раз перевипустити refresh-токен через наявний `auth.py link` → `watch.py`, а нагадування «Оновити YouTube-токен» видалити.
2. **`studio/util.py` (новий файл, ~60 рядків):** `locked_update(path, fn)` (fcntl.flock + tmp + `os.replace`), `req(url, ...)` з timeout, backoff на 429/5xx (1, 4, 16 с) і ідентифікатором джерела, `run(job)` як контекст-менеджер, що пише `runs` і шле в бот при помилці. Далі по одному файлу: `yt.py` (api, token), `lake.py`, `analytics_db.py`, `ideas.py`, `post_comments.py`, `finalize.py`, `activity.py`, `gtts.py`. Поведінка не змінюється, лише обгортки.
3. **Ідемпотентна заливка:** `yt.upload(..., slug)` спершу перевіряє `uploaded.json` і останні 10 відео каналу, а id записує відразу. `post_comments.py` перед `del` перевіряє `comments.json`.
4. **Одна гілка:** у промптах тригерів прибрати push у `claude/inspiring-…` (питання власнику, якщо гілка комусь потрібна).
5. **Схема:** міграція з розділу 5 у `lake.db()` і `analytics_db.db()` (`create … if not exists`, ALTER з перевіркою `pragma table_info`). Бекфіл `publications` з `uploaded.json`, `experiments.json`, `tiktok.json.posted_auto`, front matter `telegram_post`/`youtube`.
6. **`analytics_db.sync()`:** додати `estimatedMinutesWatched,subscribersLost`; traffic по днях; раз на тиждень `retention` для відео віком 7 днів (1 запит на відео) і `search_terms`. Валідація `avg_pct ≤ 100`, інакше `NULL` і запис у `runs.err`. `hq_data.py` бере години з бази (`creatorContentType==VIDEO_ON_DEMAND`, 365 днів).
7. **Новини:** `canonical`, `story_id`, вікно 14 днів для RSS, дата Anthropic зі сторінки статті (1 запит на нову статтю). `lake.py news` пише `runs`.
8. **Черга:** статуси в `ideas` + `ideas.py next` (наступний слот без сценарію). Диспетчер і COO читають `ideas.py board/next` замість неіснуючого `queue.json`. Перехід статусу роблять скрипти: `finalize` PASS → `scheduled`, `post_comments`/перевірка public → `done` + `content_id`.
9. **Атрибуція:** у `meta.py` посилання на сайт з `?utm_source=youtube&utm_medium=short&utm_content=<vid>`; окремі TG invite-лінки для YouTube, TikTok, сайту і реклами (розширити `ad_links.json`); вебхук пульта пропускає `chat_member` у чергу, `tg_daily` рахує вступи за лінками.
10. **Studio-експорт:** раз на тиждень власник вивантажує CSV (Reach: покази, CTR, «shown in feed / viewed») у `studio/data/exports/`, а `lake.py import-studio` кладе його в `studio_export`. Обкладинки тестувати через «Test & compare», а `thumb_test.json` використовувати як журнал.
11. **Щоденний звіт** `lake.py daily-report`: вчорашні публікації за платформами, топ і низ за 7 днів, нові пошукові терміни, топ-5 `story_id` без ідеї (кандидати), прогалини (слоти без сценарію, `runs.ok=0`, квота). Виводить у HQ `data.json` і одне повідомлення в бот. Owner — Аналітик даних; інші дашборди позначити як архівні.
12. **Фактчек Shorts:** `FACTS=[...]` у `epNN.py` і `*_factcheck.md` від незалежного агента. Диспетчер уже має правило «без PASS не озвучувати», треба лише механічно перевіряти наявність файлу.
13. **Вікно вето (за рішенням власника):** за 2 год до `publishAt` бот надсилає назву, обкладинку і посилання; на «стоп» ролик лишається private (без видалення).
