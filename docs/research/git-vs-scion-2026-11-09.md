# Git vs Scion — довгий IT, вт 10.11 17Z (~10 хв). Запит власника 9.11.
Першоджерело (відкрито 9.11.2026): https://www.anthropic.com/engineering/redesigning-source-control —
«Redesigning source control at Anthropic», 13.10.2026 (оновл. 15.10), Nick G. і команда source control.

## Факти (з поста; цифри — дані Anthropic про себе)
- Злиття в монорепо: ~2 500/день (травень 2026) → 30 000+/день (вересень).
- Історія main ~100 ГБ; стиснута робоча копія >25 ГБ.
- ~25 млн CI-checkout на день; «наївний» fetch дав би >600 ПБ git-трафіку на добу.
- На піку — кілька сотень внутрішніх git-дзеркал.
- Git — офлайн, повна копія; майже всі клієнти тепер — завжди онлайн агенти і джоби.
- Scion: сервер рахує історію, blame, коміти, злиття, rebase; клієнт `scn` тримає обмежений кеш і тягне дані на вимогу.
- Одиниця — changeset у write-ahead log; файли відносно першого батька, вказівники на blob-сховище за вмістом.
- Похідні дані (blame, історія шляху, пошук) рахуються з батьківських changeset.
- Рівні: scion-daemon (на вузлі) → scion-cache (регіон, >99% влучань) → scion-server (Spanner / хмарне сховище).
- Sparse/віртуальні checkout; без packfile → без обслуговування репо.
- Результати (їхні): ~200× менше CPU і пам'яті, ніж старі git-дзеркала; checkout для CI — з хвилин до секунд; +25% CPU-ємності CI.
- Міграція — 5 місяців; команда з 7 людей зробила Scion, код-рев'ю Antique і ~6 суміжних систем, поки злиття виросли в 10×.
- Супутні: Antique (рев'ю), пошук коду, IAM з правами на теки, семантичні правила схвалення.
- Несумісний з git-протоколом; перехід = заміна рев'ю, пошуку, CI.
- Публічно НЕ випускають. Попередники: Google Piper, Meta Sapling (Mononoke, Bonsai).
- Цитата (одна, <15 слів): «by no means a suitable replacement for git for general use».

## Не плутати
Google Scion (open source, 2026) — інше: запуск кількох кодинг-агентів у контейнерах. У ролику уточнити одним реченням.
