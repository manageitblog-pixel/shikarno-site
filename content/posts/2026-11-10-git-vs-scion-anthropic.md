У жовтні Anthropic розповіла, що замінила git у своєму головному репозиторії власною системою **Scion**. Причина — ШІ-агенти: вони пишуть і зливають код у темпі, під який git ніколи не проєктували. Розбираємо на пальцях і в реальному терміналі.

> Не плутай з проєктом Google, який теж називається Scion: там ідеться про запуск кількох кодинг-агентів у контейнерах.

## Що сталося: цифри Anthropic

Усі цифри — з посту самої компанії.

| Що | Значення |
|---|---|
| Злиттів коду на день, травень 2026 | ~2 500 |
| Злиттів коду на день, вересень 2026 | 30 000+ |
| Історія головної гілки | ~100 ГБ |
| Checkout-ів для CI на день | ~25 млн |
| Git-трафік на добу, якби качати «в лоб» | 600+ ПБ |

## Як працює git — і що показав наш термінал

Git — розподілена система: у кожного повна копія всієї історії, працювати можна офлайн. Ми клонували сам репозиторій git 10.11.2026:

| Спосіб | Час | Розмір | Що ламається |
|---|---|---|---|
| `git clone` (повний) | 36,9 с | 324 МБ, 82 797 комітів | нічого, але це «важко» |
| `git clone --depth 1` | 5,2 с | 14 МБ | історії 1 коміт, `blame` приписує все останньому коміту |
| `git clone --filter=blob:none --sparse` | 13,3 с | 121 МБ | `blame` 4,8 с замість 0,2 с — файли докачуються з сервера |

Тепер помнож на масштаб: історія Anthropic приблизно в 300 разів більша, а клієнтів — мільйони запусків на день.

## Чому git зламався

- Клієнти тепер не люди з ноутбуками, а агенти й CI-завдання: завжди онлайн, живуть хвилини, запускаються мільйонами.
- Часткові клони роблять історію й `blame` важкими, знімки репо в хмарі відстають від main.
- Внутрішніх git-дзеркал на піку було кілька сотень, і вони перестали масштабуватися, коли репозиторій переріс їхній диск і пам'ять.

## Як влаштований Scion

| Git | Scion |
|---|---|
| Повна копія в кожного | Лише кеш і потрібні файли |
| Працює офлайн | Завжди онлайн |
| Коміт = знімок усього дерева | Changeset = список змін у журналі (write-ahead log) |
| Історію й blame рахує клієнт | Рахує сервер, один раз |

Три рівні: **scion-daemon** на кожній машині, регіональний **scion-cache** (за даними Anthropic, понад 99% влучань на кожному рівні) і головний **scion-server** (метадані — у Spanner, файли — у хмарному сховищі). Клієнт `scn` починає з кореня дерева і просить лише ті папки й файли, яких бракує; кожен запит — незмінний об'єкт, тож відповісти може будь-який кеш.

## Результати (за даними Anthropic)

- у **200 разів** менше CPU і пам'яті, ніж старі git-дзеркала;
- checkout для CI і досліджень — **секунди замість хвилин**;
- **+25%** вільного CPU для CI;
- міграція — **5 місяців**, команда — **7 людей** (разом із системою рев'ю і ще ~6 суміжними системами).

## Що взяти собі вже сьогодні

```bash
# частковий клон + лише потрібна папка
git clone --filter=blob:none --sparse https://github.com/git/git partial
git -C partial sparse-checkout set Documentation

# граф комітів з фільтрами шляхів: історія файлу в нас — 0,58 с → 0,10 с
git commit-graph write --reachable --changed-paths

# усе разом для великих репо
scalar clone <url>
```

Scion публічно не випускають. Але Anthropic пише, що хоче працювати з GitHub, GitLab і open-source спільнотою і чекає, що такі проблеми стануть звичними за 6–12 місяців.
